# YoPay PHP SDK

No dependencies. Copy `src/` into your project and require one file:

```php
require __DIR__ . '/yopay/src/autoload.php';
```

PHP 8.1+, curl and json. That is all — the shops this is written for run on cPanel hosting
where `composer require` is a support ticket.

## Taking a payment

```php
use YoPay\Client;

$yopay = new Client('k_live_...', 'your-api-secret', 'https://api.yopay.com.bd');

$invoice = $yopay->createInvoice('ORD-1041', 500.00, 'Bkash', [
    'customerMsisdn' => '01711111111',
    'redirectUrl'    => 'https://shop.example.com/thanks?order=ORD-1041',
]);

header('Location: ' . $invoice['checkoutUrl']);
```

Calling this again with the same `orderRef` returns the invoice you already have rather
than making a second one. That is what makes a double-clicked checkout button harmless —
you do not need a lock around it.

**Show `chargedAmount`, not `amount`.** YoPay may adjust the figure by a few poisha so the
incoming amount is unambiguous on that wallet, and `chargedAmount` is what the customer
must actually send. Tell them the wrong number and the payment will not match.

## Receiving the result

Two things have to happen, and neither replaces the other.

```php
use YoPay\Signature;

$body = file_get_contents('php://input');          // raw. never json_decode and re-encode
$header = $_SERVER['HTTP_X_YOPAY_SIGNATURE'] ?? '';

if (!Signature::verifyWebhook($webhookSecret, $header, $body)) {
    http_response_code(401);
    exit;
}

$event = json_decode($body, true);

// Answer immediately. The request times out at 15 seconds, and a handler that sends an
// email first will be retried while the first attempt is still running.
http_response_code(200);
fastcgi_finish_request();

// Then confirm with the server before parting with goods. The webhook told you to look;
// this is the record.
$status = $yopay->verify(orderRef: $event['orderRef']);

if ($status['status'] === 'Paid' && !$order->isFulfilled()) {
    $order->fulfil();
}
```

Why both: the signature proves the message came from YoPay, and `verify()` proves the
payment is real. A shop that ships on the webhook body alone ships on a POST that anyone
who found the URL could have sent.

**The same notification can arrive twice.** A network failure after your server committed
looks exactly like one before it, so YoPay promises at least once and never exactly once.
Key on `X-YoPay-Delivery` or on your own order, and make a repeat do nothing — the
`!$order->isFulfilled()` above is the whole trick.

## Registering the endpoint

```php
$endpoint = $yopay->registerWebhook('https://shop.example.com/yopay-webhook');

// The only time this is ever returned. Nothing can show it again.
file_put_contents('/etc/yopay/webhook.secret', $endpoint['secret']);
```

`https://` only, on port 443 or 8443, resolving to a public address. Private, loopback and
cloud-metadata addresses are refused when you register and again at connection time.

## Cancelling

```php
$yopay->cancel(orderRef: 'ORD-1041');
```

Worth doing on an abandoned cart. Every open invoice reserves one amount on the wallet,
and a shop that never cancels slowly runs out of usable amounts.

## When a call fails

```php
use YoPay\ApiException;

try {
    $invoice = $yopay->createInvoice('ORD-1041', 500.00);
} catch (ApiException $e) {
    if ($e->unreachable()) {
        // Nothing answered, so you do not know whether it worked. Retrying the same
        // orderRef is safe and is the right move.
    }

    error_log('YoPay: ' . $e->getMessage() . ' (' . $e->status() . ')');
}
```

## Verifying against another language

`tests/vectors.json` holds signatures generated by the server itself. If you port this to
another language, check against that file rather than against your reading of the docs —
that is how this SDK is tested.
